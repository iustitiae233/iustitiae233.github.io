训练好的模型怎么把概率变成文字？**一个 token 一个 token 地猜，猜完接回去再猜。** 这篇讲生成过程的工程细节——决定了同一个模型是"又快又好用"还是"又慢又复读"。训练管线见 [[llm-training-pipeline]]，注意力本身见 [[self-attention]]。本分类全部笔记见 [AI 原理](/notes/ai/)。

## 一、自回归生成

| 步骤 | 内容 |
|---|---|
| 1 | 输入 prompt：`"请写一首关于春天的"` |
| 2 | 模型算出所有候选 token 的概率 → `"诗"`（85%） |
| 3 | 把 `"诗"` 追加到序列，重新输入：`"请写一首关于春天的诗"` |
| 4 | 再算概率 → `"，"` 或换行 |
| 5 | 重复，直到输出结束符 `[EOS]` 或达到最大长度 |

每一步都依赖上一步的输出，这就是"自回归"的含义，也解释了为什么 LLM **不能并行生成一整段文字**——只能逐个 token 地续写。这一点和训练时的差别很大：训练时整句话已经在手上，所有位置的预测可以一次性并行算出来（这叫 teacher forcing）；推理时没有未来，只能串行。

## 二、四个关键解码参数

| 参数 | 作用 | 典型设置 |
|---|---|---|
| **Temperature** | 把 logits 除以温度后再送进 Softmax。低温 → 分布更尖锐、输出更确定；高温 → 分布更平坦、输出更有创意 | 0.1–0.3（严谨），0.7–1.0（创意） |
| **Top-p（核采样）** | 只从累积概率达到 p 的最小 token 集合中采样，截断低概率长尾 | 0.9–0.95 |
| **Top-k** | 只从概率最高的 k 个 token 中采样 | 40–50 |
| **Repetition Penalty** | 对已出现过的 token 施加惩罚，抑制无限重复 | 1.0–1.2 |

**为什么需要这些技巧？** 如果每步都取概率最高的 token（贪心解码），输出会非常呆板甚至开始复读——因为自然语言本就不是确定性的，同一个意思有无数种表达。适度的随机性让输出更像人写的。

反过来说，**温度调到 0 也确实是可用的**：翻译、代码补全、结构化抽取这类有明确正确答案的任务，就是要确定性。参数没有"最好"，只有匹不匹配任务。

## 三、KV Cache——推理加速的关键

自回归生成每多一个 token，序列就长一个。如果每次都重新为所有 token 计算 Key 和 Value，计算量按 $O(n^2)$ 增长。

**KV Cache 的思路很简单：前面 token 的 Key 和 Value 不会变化，缓存起来就行。** 生成第 $N+1$ 个 token 时，只需算这一个新 token 的 Q、K、V，然后让它去"关注"缓存里的全部 K 和 V。

| | 每生成一个 token 的注意力代价 |
|---|---|
| 无缓存 | $O(n^2)$——重算整条序列 |
| **有 KV Cache** | $O(n)$——只算新 token 的 Q，与缓存的 K/V 做一次注意力 |

这是实际部署中最重要的单项加速技术。代价是显存：缓存大小与层数、头数、维度、序列长度成正比，长上下文场景下 KV Cache 往往比模型权重本身还占地方——后续的一系列优化（MQA / GQA 共享 K/V 头、分页管理、量化缓存）都是在压这个开销。

## 四、量化——把权重压小

另一个正交的加速方向是**量化**：把权重和激活从 FP16 降到 INT8 / INT4 等低位宽表示，直接减少显存占用与内存带宽需求。因为大模型推理常常卡在**带宽**而不是算力上，位宽减半往往能换来接近翻倍的吞吐。

代价是数值精度损失，需要标定（calibration）来控制误差；实践中 8 位几乎无损，4 位则要看具体方案与任务。

## 小结

| 要点 | 结论 |
|---|---|
| 自回归 | 逐 token 串行生成，无法并行——与训练的 teacher forcing 形成对比 |
| Temperature | 控制分布尖锐程度；严谨任务调低，创意任务调高 |
| Top-p / Top-k | 截断长尾，避免采到荒谬的 token |
| Repetition Penalty | 抑制复读，但过大会破坏正常重复（如代码里的变量名） |
| KV Cache | 缓存历史的 K/V，每步 $O(n^2) \to O(n)$，代价是显存 |
| 量化 | 降位宽省带宽与显存，8 位基本无损，4 位需权衡 |

*推理侧的优化几乎全在同一个命题上做文章：**别重复计算已经算过的东西**——KV Cache 缓存状态，量化压缩存储，两者共同把"能跑起来"变成"跑得起"。*
