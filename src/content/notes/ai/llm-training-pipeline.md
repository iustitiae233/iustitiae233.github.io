一个能对话的模型不是一次训练出来的，而是**三段目标完全不同**的训练接力：预训练灌知识、SFT 教格式、RLHF 对齐偏好。算力与数据规模如何配比见 [[scaling-laws]]，生成时的解码策略见 [[llm-inference-and-decoding]]。本分类全部笔记见 [AI 原理](/notes/ai/)。

## 一、阶段一：预训练——"读完整个互联网"

预训练是 LLM 生命周期里成本最高、耗时最长的阶段。GPT-3 用了约 3000 亿个 token，在数千块 GPU 上训练数月，外界估算成本在 500 万到 1200 万美元量级。

**训练数据构成**（以 LLaMA 2 为代表的开源配方，按论文口径）：

| 数据来源 | 占比 | 说明 |
|---|---|---|
| Common Crawl | 67.0% | 互联网公开网页，经过严格的质量过滤 |
| C4 | 15.0% | 另一份清洗过的网页语料 |
| GitHub | 4.5% | 代码——带来逻辑推理与形式化语言能力 |
| Wikipedia | 4.5% | 事实性与世界知识 |
| Books | 4.5% | 长篇叙事与结构化知识 |
| ArXiv | 2.5% | 学术论文，科学推理 |
| StackExchange | 2.0% | 问答社区，技术讨论与解释性文本 |

注意这份配方的结构：**网页语料占了 82%，其余全部加起来不到 20%**——但正是那不到 20% 的"高密度语料"（代码、书籍、论文、问答）决定了模型推理能力的上限。这也是各家模型配方里最不肯公开的部分。

**训练目标**：最简单的交叉熵损失——对每个位置，最大化模型预测正确 token 的概率。整个互联网就是训练数据，每一句话都是自动标注的样本。分词与自监督样本的构造见 [[tokenization-and-embedding]]。

**产出物：基座模型（Base Model）**。它"知道"大量知识，能完美续写文本，但**不太擅长对话**——你问它一个问题，它可能回你更多问题，因为它学会的唯一一件事是"续写"，而不是"回答"。

## 二、阶段二：SFT——"学会对话格式"

监督微调（Supervised Fine-Tuning, SFT）教基座模型"当人类发出指令时，应该给出有帮助的回答"。

| 维度 | 内容 |
|---|---|
| 训练数据 | 数万到数十万条人工编写的"指令 → 高质量回答"对，覆盖问答、摘要、翻译、代码、创意写作 |
| 训练方式 | 和预训练完全一样——仍然预测下一个 token，只是数据与格式变了 |
| 关键格式 | 数据被格式化为对话模板，如 `<|user|>请解释量子计算<|assistant|>量子计算是……`，模型从中学会角色交替结构 |
| 计算成本 | 相比预训练几乎可以忽略——通常几小时到一两天 |

**产出物：指令模型（Instruction Model）**。能做正常对话了，但仍有问题：可能输出不安全内容、该拒绝的不拒绝、不该拒绝的反而拒绝、风格不够自然。

## 三、阶段三：RLHF——"学会什么是对的"

**RLHF（Reinforcement Learning from Human Feedback）** 是让 ChatGPT 真正可用的最后一步。它的思路在 2017 年由 DeepMind 与 OpenAI 的偏好学习工作分别提出，2022 年因 InstructGPT / ChatGPT 的成功成为行业标杆。

**完整流程**：

| 步骤 | 做什么 |
|---|---|
| 1. 收集人类偏好数据 | 让 SFT 模型对同一个 prompt 生成多个回答（通常 4–9 个），标注员按"有用性、安全性、准确性"排序 |
| 2. 训练奖励模型 | 基于 SFT 模型训练一个打分网络：输入 (prompt, 回答) 对，输出一个标量奖励分，目标是让打分与人类排序一致 |
| 3. 用 PPO 微调 | 把语言模型当作强化学习中的"策略"，生成回答 → 奖励模型打分 → 用 PPO（Proximal Policy Optimization）更新参数，使模型倾向生成高奖励回答 |
| 4. KL 散度约束 | 目标中加入一项 KL 惩罚，约束新模型不要离 SFT 模型太远 |

第 4 步最容易被忽略却最关键：**没有 KL 约束，模型会学会"刷分"**——找到奖励模型的漏洞，输出人类看来莫名其妙的文本却拿到高分。约束离原始模型的距离，等于给优化过程装了一个护栏。

**DPO（Direct Preference Optimization）** 是 2023 年出现的方法，它不需要单独训练奖励模型，直接从人类偏好数据里学。数学上可以证明它与带 KL 约束的 RLHF 目标等价，但工程上简单得多——退回成一次监督学习即可。很多开源模型（如 Zephyr）就是用 DPO 训练的。

> 💡 RLHF 不会让模型"变聪明"——知识在预训练阶段就已经定下了。它做的是**对齐（Alignment）**：让输出更符合人类期望。一个没做过 RLHF 的基座模型和它对标的对话模型，知道的"事实"完全一样，差别只在于呈现方式。

## 小结

| 阶段 | 目标 | 数据 | 成本 |
|---|---|---|---|
| 预训练 | 灌入知识与语言能力 | 数万亿 token 的网页 + 高密度语料 | 最高，数百万美元级 |
| SFT | 学会"回答问题"的格式 | 数万到数十万条指令-回答对 | 极低，小时到天 |
| RLHF | 对齐人类偏好 | 人类排序的偏好数据 | 中等，需训练奖励模型 + PPO |
| DPO 替代 | 同样的对齐目标 | 同样的偏好数据 | 比 RLHF 简单，无需奖励模型 |

*三阶段的分工可以这样记：预训练决定模型"知道什么"，SFT 决定它"怎么说话"，RLHF 决定它"愿不愿意好好说"。*
