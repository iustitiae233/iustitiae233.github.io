模型不认识字，只认识向量。从一段中文到一个能送进网络的张量，中间要经过三道工序：**切成 token、查表变向量、补上位置信息**。做完这三步，才轮到 [[self-attention]] 登场。本分类全部笔记见 [AI 原理](/notes/ai/)。

## 一、核心任务简单到不可思议

大语言模型（Large Language Model, LLM）的核心任务只有一个：**给定前文，预测下一个词**。

输入"天安门广场上升"，模型要给出下一个位置的概率分布：

$$P(\text{"旗"} \mid \text{"天安门广场上升"}) = 0.73, \quad P(\text{"起"}) = 0.12, \quad P(\text{"了"}) = 0.05, \quad \dots$$

然后按这个分布选一个（或取概率最高的），把它接到序列后面，再重复一遍。

> 💡 GPT 系列训练**不需要任何人工标注**。互联网上任意一段文本都能自动拆成"前文 → 下一个词"的样本：取前 N 个词作输入，第 N+1 个词就是标准答案。这种自监督学习意味着训练数据几乎取之不尽——整个互联网的文本都是免费的标注。

## 二、语言模型的进化史

| 时代 | 方法 | 核心思路 | 致命弱点 |
|---|---|---|---|
| 1950s–1990s | n-gram 模型 | 统计"前 n−1 个词出现时，第 n 个词是什么" | 抓不住长距离依赖；n 每加 1，参数量指数爆炸 |
| 2010–2015 | RNN / LSTM | 循环处理序列，隐状态携带历史信息 | 串行计算慢；梯度消失导致实际只能记住几十步 |
| 2014–2016 | Seq2Seq + Attention | 编码器压缩句子，解码器"关注"编码器的相关部分 | 注意力只用于连接编码器与解码器，不是自注意力 |
| 2017 | **Transformer** | 完全抛弃循环，用自注意力同时看到全文 | 计算复杂度 $O(n^2)$，长文本成本高 |
| 2018 | GPT-1 / BERT | Transformer + 大规模预训练 | 需要大量算力 |
| 2020 | GPT-3 | 1750 亿参数，零样本 / 少样本学习 | 推理成本高昂 |
| 2022–2023 | ChatGPT / GPT-4 | RLHF 对齐 + 多模态 | 训练成本达数亿美元 |

转折点是 2017 年的《Attention Is All You Need》——它证明序列建模**不一定需要循环结构**，这一刀把 RNN 从主路上砍了下去。

## 三、Token——模型眼中的最小语义单元

模型处理的既不是"字"也不是"词"，而是 Token。

```
英文: "Hello, world!"      → ["Hello", ",", " world", "!"]      // 4 个 token
中文: "神经网络很强大"      → ["神经", "网络", "很", "强大"]      // 4 个 token
代码: "def hello():"       → ["def", " hello", "():"]          // 3 个 token
```

英文 13 个字符只用了 4 个 token，中文 6 个字也用了 4 个——因为常见英文单词和常见中文双字词都在词汇表里有独立编码。分词算法的目标就是"**常见内容一个 token 装下，生僻内容拆成多个**"。

## 四、BPE——最主流的切分算法

GPT 系列用的分词算法叫 **BPE（Byte Pair Encoding）**，思路是：**从字符级别开始，反复合并出现频率最高的相邻对**。

1. 把所有训练文本拆成单个字符（或字节）
2. 统计所有相邻对的频率
3. 合并频率最高的那一对（比如 `t` 与 `h` 合并成 `th`）
4. 把合并后的新单元加入词汇表
5. 重复 2–4 步，直到词汇表达到预设大小

巧处在于：**常见词（"the"、"是"）整体占一个 token，高效；生僻词（"gobbledygook"）被拆成 `gob``bled``y``gook` 几个子词 token，永远不会"不认识"**。

| 词汇表大小 | 优点 | 缺点 |
|---|---|---|
| 小（32K） | Embedding 矩阵小，训练与推理快 | 同一个词被拆成更多 token，等长语义需要更长序列 |
| 大（100K+） | 同样文本产生更少 token，信息密度高 | Embedding 矩阵大，参数量与内存上升 |
| 多语言大（250K+） | 覆盖语言多，不必额外适配 | 罕见 token 的 Embedding 训练不充分 |

**上下文窗口是按 token 计的，不是按字数计的。** 中文的分词效率明显低于英文——同一个汉字常常要花掉一个以上的 token，生僻字更多。所以标称"128K 上下文"的模型，实际能装下的中文篇幅会明显少于 128K 个汉字。

## 五、Embedding——从离散符号到连续语义空间

Token 是离散整数 ID（"猫" = 1523，"狗" = 8764），神经网络只吃连续实数向量。**Embedding** 就是这座桥——实质是一张巨大的查找表，尺寸为 [词汇表大小 × 嵌入维度]。

以 GPT-3 为例：词汇表 50257 个 token，嵌入维度 12288，于是每个 token 对应一个 12288 维稠密向量，整张表约 $50257 \times 12288 \approx 6.18$ 亿个参数——**光是分词后的第一层查表，参数就比大多数完整模型还多。**

这张表不是人写的，是反向传播一步步"挪"出来的：语义相近的词在向量空间里逐渐靠近，无关的词逐渐远离。训练结束时它是一张精密的"语言宇宙地图"。

## 六、位置编码——让 Transformer 知道顺序

Transformer 有一个特殊性质：它**同时处理所有位置的 token**，不像 RNN 那样按顺序读。这是它高效的原因，也带来一个问题——如果不做特殊处理，模型根本不知道"我"在"你"前面还是后面。位置编码就是给每个 token 贴一个位置标签。

| 类型 | 代表 | 原理 | 优缺点 |
|---|---|---|---|
| 正弦位置编码 | 原始 Transformer | 用不同频率的正弦/余弦函数为每个位置生成唯一编码 | 不需要学习，但外推到训练长度以外效果差 |
| 可学习位置编码 | BERT、GPT-2 | 位置编码也是可训练参数 | 灵活，但最大长度被固定死 |
| **旋转位置编码（RoPE）** | LLaMA、GPT-NeoX、Qwen | 用旋转矩阵把位置信息编进注意力计算，而非加到 Embedding 上 | **相对位置天然编码**、可外推到更长序列，现代 LLM 标配 |

**RoPE 的核心直觉**：它不告诉模型"这是第 5 个 token"，而是在算注意力时注入两个 token 之间的**相对位置差**。模型理解的是"这两个词相距 3 个位置"而不是"它们分别在位置 5 和 8"——前者更容易外推到比训练时更长的序列。

## 小结

| 要点 | 结论 |
|---|---|
| 核心任务 | 预测下一个 token；自监督意味着数据几乎无限 |
| Token | 不是字也不是词，而是统计上高频的片段 |
| BPE | 从字符起步，反复合并最高频相邻对 |
| 词汇表权衡 | 小则序列长、大则矩阵大；中文的 token 效率低于英文 |
| Embedding | [词表 × 维度] 的查找表，GPT-3 光这张表就 6 亿参数 |
| 位置编码 | 正弦 → 可学习 → RoPE，现代 LLM 用 RoPE 以支持长序列外推 |

*分词决定模型"看世界的粒度"，嵌入决定它"把世界放在哪"，位置编码决定它"知道先后"——三步之后，语言才终于变成可以并行计算的矩阵。*
