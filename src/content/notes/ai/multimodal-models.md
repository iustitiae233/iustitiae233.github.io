让语言模型"看图"这件事，工程上的答案出奇地简单：**把图像编码成一批 token，和文本 token 拼在一起送进去**。难点不在拼接，而在对齐——让"猫"这个词和猫的像素出现在同一个语义空间里。视觉编码器本身见 [[vit]]，注意力机制见 [[self-attention]]，本分类全部笔记见 [AI 原理](/notes/ai/)。

## 一、为什么需要多模态

纯语言模型只能处理文本——它知道"苹果是红色的圆形水果"这个陈述，但从没见过真实的苹果。混合视觉信息后，模型能建立**文本概念与视觉实在之间的直接联系**，这对世界理解、空间推理和常识判断都至关重要。

## 二、主流架构：外挂式三件套

目前最主流的做法是**视觉编码器 + 投影层 + 语言模型**：

$$\text{图像} \to \text{视觉编码器（ViT / SigLIP）} \to N \text{ 个视觉 token} \to \text{投影层（MLP）} \to \text{与文本 token 拼接} \to \text{LLM} \to \text{回答}$$

| 部件 | 职责 |
|---|---|
| **视觉编码器** | 把图像转成一系列视觉特征向量。通常用 ViT，或用 SigLIP（CLIP 的改进版，见下） |
| **投影层（Projector）** | 一个简单的 MLP，把视觉向量映射到与文本 Embedding 相同的维度空间，让 LLM 能统一处理 |
| **LLM** | 像处理文本 token 一样处理视觉 token——拼接后一起做自注意力 |

本质上这是在 LLM 上"外挂"了一个视觉前端——视觉编码器负责"看"（提取特征），LLM 负责"想"（基于视觉与文本做推理）。**LLM 的"思考方式"没有被改变，只是它能处理的信息类型被扩展了。**

### 三条融合路线的差别

按视觉与语言在什么阶段汇合，可以把多模态模型分成三类——**这个分类比记住具体模型型号更有用，因为型号一年一换、路线很少变**：

| 路线 | 融合发生在 | 特点 |
|---|---|---|
| **外挂式（Late Fusion）** | 视觉编码器输出之后，用 MLP 投到文本空间再拼接 | 工程最简单：视觉前端和语言模型可以各自独立训练再对齐。开源多模态模型多走这条路 |
| **交叉注意力融合** | LLM 内部用交叉注意力层去"查询"视觉特征 | 视觉与语言交互更充分，代价是结构更复杂、训练更难 |
| **原生多模态（Early Fusion）** | 从预训练第一天起就把图像与文本混在同一个序列里训练 | 模态间的对齐最彻底，也最昂贵；需要对两种模态同时做大规模预训练 |

选哪条路本质上是**"对齐质量"与"训练成本"之间的取舍**。外挂式的性价比最高，所以成了主流；Early Fusion 的上限更高，但只有少数团队付得起那笔预训练账。

> 💡 一个常见误解是"多模态模型有专门的图像理解模块"。实际上外挂式架构里，**LLM 见到的只是一串数字向量**——它并不知道哪些 token 来自图像。所谓"看图"，就是把视觉特征翻译成了 LLM 本来就在处理的那种语言。

## 三、CLIP——连接文本与视觉的桥梁

**CLIP（Contrastive Language-Image Pre-training, OpenAI, 2021）** 本身不是生成模型，却是几乎所有现代多模态系统的核心组件。设计极其优雅：

| 步骤 | 内容 |
|---|---|
| 1 | 收集约 4 亿个"图片-文本描述"对 |
| 2 | 训练一个图像编码器和一个文本编码器，让匹配的图文对 Embedding 尽量相似、不匹配的尽量远离 |
| 3 | 训练方式：在一个 batch 内做对比学习——正确的图文对是正样本，同 batch 内其他所有图文组合都是负样本 |

训练完成后得到一个**语义对齐空间**：图片"一只猫"和文字"猫"距离很近，和文字"狗"距离很远。这个空间是文本控制图像生成的基础（[[diffusion-models]]），也是多模态模型"看懂"图像的前提。

注意第 3 步的巧妙之处：**监督信号不来自人工标注，而来自"配对关系本身"**——4 亿对数据里，每一对的正确答案就是"它俩配一对"。这让 CLIP 能吃下互联网规模的弱标注数据。代价是它只学到"图文是否匹配"这种粗粒度对齐，不擅长细粒度空间关系（比如"左边的猫在右边狗的后面"）。

## 四、注意力的瓶颈在视觉上被放大

自注意力的 $O(n^2)$ 复杂度在这里格外致命——文本序列再长也就几十 K token，而一张 1024×1024 的图像对应约 4096 个 ViT patch，直接送进注意力就是 $4096^2$ 的分数矩阵，高分辨率场景下很快失控。

当前的应对方向（机制本身见 [[self-attention]]）：

| 方向 | 思路 |
|---|---|
| Flash Attention | 软硬件协同优化，不改变复杂度但把常数与访存压到极致，已是标配 |
| 状态空间模型（Mamba、RWKV） | 直接换掉注意力，做到线性复杂度 |
| 混合架构 | 局部窗口注意力（高效）+ 少量全局 token（长程依赖），兼顾两者 |
| 视觉侧降 token | 池化 / 合并 patch / 用更激进的压缩编码器减少视觉 token 数量 |

## 五、世界模型——下一个前沿

Yann LeCun（图灵奖得主）长期倡导"世界模型"的理念：AI 不应该只识别物体或生成图片，而应该拥有一个**内在的世界模拟器**——能预测物理世界的演变、推理因果关系、在想象中规划行动。

视频生成模型在某种程度上展示了这种可能性：生成的视频不仅画面连贯，物体在空间中的运动和遮挡关系也符合物理直觉。这暗示**模型在学习视频生成的同时，也学到了某种隐式的三维世界模型**——它必须"知道"物体转过身后会被遮挡，才能生成出合理的下一帧。

需要谨慎的是：这类证据是**间接的**。视频连贯性也可能来自对训练分布的强记忆，而不代表模型真的在做物理推理。如何区分"内化了物理规律"与"见过足够多的相似片段"，是这个世界模型路线当前最核心的未解问题。

## 小结

| 要点 | 结论 |
|---|---|
| 外挂式架构 | 视觉编码器 → 投影层 → 与文本 token 拼接 → LLM |
| 三条融合路线 | Late Fusion（简单）→ 交叉注意力（更充分）→ Early Fusion（最彻底也最贵） |
| 关键部件 | 投影层负责把视觉向量搬进文本空间，LLM 本身不区分模态 |
| CLIP | 4 亿图文对 + 对比学习，造出图文对齐空间，是多模态的地基 |
| 注意力瓶颈 | 视觉 token 数量远大于文本，$O(n^2)$ 在这里被放大 |
| 世界模型 | 视频生成暗示了隐式物理理解，但"真推理"与"强记忆"尚难区分 |

*多模态的工程本质是"翻译"：把图像翻译成语言模型已经在用的那种表示，然后让它继续做它最擅长的事——预测下一个 token。真正做到"理解"，可能还需要那个尚未被证明存在的内在世界模型。*
