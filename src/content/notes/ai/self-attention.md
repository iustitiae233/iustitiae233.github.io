注意力是 Transformer 里唯一不可替代的部件——它让序列中的每个位置都能直接看到其他任意位置。**这是本站关于注意力机制的唯一详解**，其余笔记遇到它一律指回本篇。整体架构见 [[transformer-architecture]]，视觉侧的同类改造见 [[vit]]，本分类全部笔记见 [AI 原理](/notes/ai/)。

## 一、为什么需要注意力

看这个句子：**"小明把苹果给了小红，因为她很饿。"**

谁饿了？人类能通过"因为"和"给了"的语义关系推断出是小红饿了。RNN 只能看到距离最近的前几个词，很难跨越"给了小红"去把"她"和"小红"连起来。

注意力要解决的就是这个问题：**让每个词都能直接"看到"句子中任何其他词，并根据语义自动决定该关注谁。**

## 二、缩放点积注意力——逐步拆解

### 第一步：生成 Q、K、V 三组向量

对每个 token 的 Embedding，用三个不同的权重矩阵 $W_Q$、$W_K$、$W_V$ 分别投影，得到三组独立向量：

| 向量 | 全称 | 代表什么 |
|---|---|---|
| **Q** | Query（查询） | 这个 token "在寻找什么" |
| **K** | Key（键） | 这个 token "能提供什么信息" |
| **V** | Value（值） | 这个 token "实际含有什么内容" |

> 💡 把 Transformer 想象成一个图书馆。你是读者，想找"关于神经网络的入门书"——这就是 Query。每本书封面上印着标签（Key）说明自己能提供什么。管理员拿你的 Query 与每本书的 Key 做匹配，再按匹配程度从最相关的书里提取内容（Value）拼成你的专属答案。生成 Q、匹配 K、聚合 V，就是自注意力的全部。

### 第二步：计算注意力分数

$$\text{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

拆开看每一项：

- $QK^{\top}$——一次矩阵乘法，算出每个 token 的 Query 与所有 token 的 Key 之间的点积（相似度）。结果是一个 $N \times N$ 方阵，第 $i$ 行第 $j$ 列表示"第 $i$ 个 token 该关注第 $j$ 个多少"。
- $\sqrt{d_k}$——**缩放因子**，$d_k$ 是 Key 的维度（通常 64 或 128）。维度大时点积的方差也大，Softmax 的输入里会出现少数极大值和大量极小值，梯度几乎为零。除以 $\sqrt{d_k}$ 把输入拉回合理范围。
- $\mathrm{softmax}$——把每行的相似度变成和为 1 的概率分布，也就是权重。

### 第三步：加权求和

用这些权重对每个 token 的 Value 加权求和，得到该位置的输出——本质是"**按相关性程度聚合全序列的信息**"。

## 三、多头注意力——多角度同步理解

一组 Q/K/V 只能捕捉一种关注模式。**多头注意力（Multi-Head Attention）** 并行跑多组独立注意力（GPT-3 有 96 个头），每组关注语言的不同侧面：

| 头类型 | 关注什么 |
|---|---|
| 语法头 | "动词-宾语"、"形容词-名词"等句法依赖 |
| 指代头 | 追踪代词（"他"、"她"、"它"）指向的实体 |
| 语义头 | 同义关系与上下位关系 |
| 位置头 | 相邻或近距 token 之间的局部模式 |
| 情感 / 语气头 | 表达情感和态度的词 |

把所有头的输出拼接起来，再做一次线性投影，得到多头注意力的最终输出。

（这些分工不是人工指定的，是从数据里学出来的——可解释性研究通过观察注意力图反推出上述模式，而非反过来设计。）

## 四、O(n²) 的瓶颈与 Flash Attention

自注意力让每个 token 与所有其他 token 两两交互，复杂度是 **$O(n^2)$**——序列长度翻倍，计算量翻四倍。对 128K 的上下文窗口，每个注意力层里都有一个 $128000 \times 128000$ 的分数矩阵。

目前最主流的解法是 **Flash Attention**：它**不改变数学结果**，而是重排计算顺序以利用 GPU 的内存层次。GPU 有大容量高带宽内存（HBM，如 80GB）和快得多但只有约 20MB 的 SRAM。传统实现必须把完整的 $N \times N$ 矩阵写进 HBM 再读回来；Flash Attention 把计算切成小块，每块在 SRAM 里算完就合并，**从不把完整矩阵物化到 HBM**。带来 2–4 倍加速与 10–20 倍显存节省，已是所有 LLM 推理引擎的标配。

> ⚠️ Flash Attention 优化的是**常数与访存**，不是复杂度——它依然是 $O(n^2)$。真正想突破这一层，得换掉注意力本身（状态空间模型 Mamba / RWKV 那条线性复杂度的路线），或用局部窗口 + 全局 token 的混合架构。见 [[scaling-laws]] 的讨论。

## 小结

| 要点 | 结论 |
|---|---|
| 三组向量 | Q 在找什么、K 能提供什么、V 实际是什么 |
| 公式 | $\mathrm{softmax}(QK^{\top}/\sqrt{d_k})V$ |
| 为什么要缩放 | 维度大 → 点积方差大 → Softmax 梯度消失 |
| 多头 | 并行多组 Q/K/V，各组学到不同的关注模式 |
| 复杂度 | $O(n^2)$，序列长度翻倍计算量翻四倍 |
| Flash Attention | 分块在 SRAM 内完成，不物化完整矩阵；省显存省带宽，但复杂度不变 |

*注意力用一次 $N \times N$ 的两两比较，换来了"任意两个位置直接对话"的能力——这笔交易的代价随长度平方增长，而它的价值也正来自这里。*
