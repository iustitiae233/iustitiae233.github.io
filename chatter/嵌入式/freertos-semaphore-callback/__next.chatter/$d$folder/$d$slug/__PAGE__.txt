30:T2a22,<h2>引言</h2>
<p>多任务操作系统中，任务不是孤岛——它们需要通信、需要同步、需要共享资源。如果说上一篇的"任务管理"让每个任务独立运行，那么本文的"信号量"就是任务之间对话的语言。</p>
<h2>一、信号量（Semaphore）—— 四种类型</h2>
<h3>1.1 二值信号量（Binary Semaphore）—— 任务同步 / 中断通知</h3>
<p>最常用的信号量类型，只有 0 和 1 两个状态，用于任务间同步或中断通知任务。</p>
<p><strong>创建：</strong></p>
<pre><code class="hljs language-cpp">SemaphoreHandle_t xSemaphore = <span class="hljs-built_in">xSemaphoreCreateBinary</span>();
<span class="hljs-comment">// 注意：创建后初始值为 0（空）！</span>
</code></pre>
<p><strong>任务中等待（Take）：</strong></p>
<pre><code class="hljs language-cpp"><span class="hljs-keyword">if</span> (<span class="hljs-built_in">xSemaphoreTake</span>(xSemaphore, portMAX_DELAY) == pdTRUE) {
    <span class="hljs-comment">// 获取到信号量，执行同步操作</span>
}
</code></pre>
<p><strong>中断中释放（GiveFromISR）：</strong></p>
<pre><code class="hljs language-cpp">BaseType_t xHigherPriorityTaskWoken = pdFALSE;
<span class="hljs-built_in">xSemaphoreGiveFromISR</span>(xSemaphore, &#x26;xHigherPriorityTaskWoken);
<span class="hljs-built_in">portYIELD_FROM_ISR</span>(xHigherPriorityTaskWoken);  <span class="hljs-comment">// 判断是否需要任务切换</span>
</code></pre>
<p><strong>典型应用场景：</strong></p>
<ul>
<li>按键中断通知任务处理</li>
<li>DMA 传输完成中断通知任务</li>
<li>两个任务之间的握手同步</li>
</ul>
<h3>1.2 计数信号量（Counting Semaphore）—— 资源池管理</h3>
<p>可以管理多个同类资源，计数值表示可用资源的数量。</p>
<pre><code class="hljs language-cpp"><span class="hljs-comment">// 最大计数 5，初始计数 3（有 3 个资源可用）</span>
SemaphoreHandle_t xCountSem = <span class="hljs-built_in">xSemaphoreCreateCounting</span>(<span class="hljs-number">5</span>, <span class="hljs-number">3</span>);

<span class="hljs-comment">// 消耗一个资源</span>
<span class="hljs-built_in">xSemaphoreTake</span>(xCountSem, portMAX_DELAY);

<span class="hljs-comment">// 归还一个资源</span>
<span class="hljs-built_in">xSemaphoreGive</span>(xCountSem);
</code></pre>
<p><strong>典型应用场景：</strong></p>
<ul>
<li>管理固定大小的缓冲区池</li>
<li>限制同时访问某资源的任务数量</li>
<li>多生产者-多消费者模型</li>
</ul>
<h3>1.3 互斥锁（Mutex）—— 资源独占 + 优先级继承</h3>
<p>用于保护共享资源（全局变量、外设、通信总线），确保同一时刻只有一个任务访问。</p>
<pre><code class="hljs language-cpp"><span class="hljs-comment">// 创建互斥锁</span>
SemaphoreHandle_t xMutex = <span class="hljs-built_in">xSemaphoreCreateMutex</span>();

<span class="hljs-comment">// 使用模式（必须在同一任务中 Take 和 Give）</span>
<span class="hljs-built_in">xSemaphoreTake</span>(xMutex, portMAX_DELAY);
    <span class="hljs-comment">// 访问共享资源（printf、I2C、SPI、全局变量）</span>
    <span class="hljs-comment">// ...</span>
<span class="hljs-built_in">xSemaphoreGive</span>(xMutex);
</code></pre>
<blockquote>
<p>⚠️ <strong>关键限制</strong>：</p>
<ul>
<li>互斥锁<strong>不能在中断中使用</strong>！</li>
<li>Take 和 Give <strong>必须在同一个任务中成对出现</strong></li>
<li>互斥锁自动支持<strong>优先级继承</strong>，防止优先级翻转问题</li>
</ul>
</blockquote>
<p><strong>优先级翻转问题</strong>：低优先级任务持有锁 → 高优先级任务等待锁 → 中优先级任务抢走 CPU。互斥锁的优先级继承机制会将持有锁的低优先级任务临时提升，避免这种情况。</p>
<h3>1.4 递归互斥锁（Recursive Mutex）</h3>
<p>普通互斥锁同一任务只能 Take 一次，递归互斥锁允许同一任务多次 Take。</p>
<pre><code class="hljs language-cpp">SemaphoreHandle_t xRecursiveMutex = <span class="hljs-built_in">xSemaphoreCreateRecursiveMutex</span>();

<span class="hljs-built_in">xSemaphoreTakeRecursive</span>(xRecursiveMutex, portMAX_DELAY);  <span class="hljs-comment">// 第一次获取</span>
    <span class="hljs-built_in">xSemaphoreTakeRecursive</span>(xRecursiveMutex, portMAX_DELAY);  <span class="hljs-comment">// 再次获取（OK！）</span>
    <span class="hljs-built_in">xSemaphoreGiveRecursive</span>(xRecursiveMutex);                  <span class="hljs-comment">// 释放一层</span>
<span class="hljs-built_in">xSemaphoreGiveRecursive</span>(xRecursiveMutex);                      <span class="hljs-comment">// 完全释放</span>
</code></pre>
<p><strong>典型应用场景</strong>：嵌套函数调用中，每个函数都可能需要获取同一个锁。</p>
<h2>二、信号量类型对比总结</h2>
<p>类型Take 次数Give 次数中断可用优先级继承典型用途<strong>二值信号量</strong>1 次（变 0）1 次（变 1）✅ Give❌任务同步、中断通知<strong>计数信号量</strong>N 次（减到 0）N 次（加到最大）✅ Give❌资源池管理<strong>互斥锁</strong>1 次1 次（同一任务）❌✅资源独占保护<strong>递归互斥锁</strong>多次（同任务）对应次数❌✅嵌套函数锁</p>
<h2>三、软件定时器与回调函数</h2>
<p>FreeRTOS 提供<strong>软件定时器</strong>，允许在定时器到期时执行回调函数。这些回调函数在<strong>定时器服务任务</strong>的上下文中运行。</p>
<h3>创建软件定时器</h3>
<pre><code class="hljs language-cpp"><span class="hljs-comment">// 定时器回调函数（不能有死循环！不能有阻塞调用！）</span>
<span class="hljs-function"><span class="hljs-type">void</span> <span class="hljs-title">TimerCallback</span><span class="hljs-params">(TimerHandle_t xTimer)</span> </span>{
    <span class="hljs-comment">// 定时执行的代码</span>
    <span class="hljs-comment">// 只能调用带 FromISR 后缀或不阻塞的 API</span>
}

<span class="hljs-comment">// 创建定时器</span>
TimerHandle_t xTimer = <span class="hljs-built_in">xTimerCreate</span>(
    <span class="hljs-string">"MyTimer"</span>,                      <span class="hljs-comment">// 名称</span>
    <span class="hljs-built_in">pdMS_TO_TICKS</span>(<span class="hljs-number">100</span>),             <span class="hljs-comment">// 周期 100ms</span>
    pdTRUE,                         <span class="hljs-comment">// pdTRUE=周期模式, pdFALSE=单次触发</span>
    (<span class="hljs-type">void</span> *)<span class="hljs-number">0</span>,                      <span class="hljs-comment">// 定时器 ID（可传参）</span>
    TimerCallback                   <span class="hljs-comment">// 回调函数</span>
);

<span class="hljs-comment">// 启动定时器</span>
<span class="hljs-built_in">xTimerStart</span>(xTimer, <span class="hljs-number">0</span>);
</code></pre>
<h3>CubeMX CMSIS-RTOS 封装方式</h3>
<pre><code class="hljs language-cpp"><span class="hljs-built_in">osTimerDef</span>(MyTimer, TimerCallback);
osTimerId timerHandle = <span class="hljs-built_in">osTimerCreate</span>(<span class="hljs-built_in">osTimer</span>(MyTimer), osTimerPeriodic, <span class="hljs-literal">NULL</span>);
<span class="hljs-built_in">osTimerStart</span>(timerHandle, <span class="hljs-number">5</span>);  <span class="hljs-comment">// 5ms 周期</span>
</code></pre>
<h3>回调函数注意事项</h3>
<p>注意点说明<strong>不能有死循环</strong>回调函数必须快速返回<strong>不能阻塞</strong>不能调用 <code>vTaskDelay</code>、<code>xSemaphoreTake</code>（带超时的也不行）<strong>不能调用非 FromISR 的 API</strong>可以使用 <code>xSemaphoreGiveFromISR</code><strong>运行在定时器服务任务中</strong>优先级通常较高，耗时操作会影响所有定时器</p>
<h2>四、任务通知 —— 更轻量的替代方案</h2>
<p>如果只需要简单的任务同步，<strong>任务通知（Task Notification）</strong> 比信号量更快，占用 RAM 更少——但一个任务只能阻塞在一个通知上。</p>
<pre><code class="hljs language-cpp"><span class="hljs-comment">// 发送通知（任务中）</span>
<span class="hljs-built_in">xTaskNotifyGive</span>(TaskHandle);

<span class="hljs-comment">// 发送通知（中断中）</span>
<span class="hljs-built_in">vTaskNotifyGiveFromISR</span>(TaskHandle, &#x26;xHigherPriorityTaskWoken);

<span class="hljs-comment">// 等待通知</span>
<span class="hljs-built_in">ulTaskNotifyTake</span>(pdTRUE, portMAX_DELAY);
<span class="hljs-comment">// pdTRUE  → 收到通知后将值清零（类似二值信号量）</span>
<span class="hljs-comment">// pdFALSE → 收到通知后将值减 1（类似计数信号量）</span>
</code></pre>
<p><strong>任务通知 vs 信号量</strong>：</p>
<ul>
<li>任务通知：更快、RAM 更少，但<strong>一个任务只能等待一个通知源</strong></li>
<li>信号量：稍慢但更灵活，可以等待<strong>任意多个信号量</strong></li>
</ul>
<h2>五、信号量 vs 队列 vs 任务通知</h2>
<p>机制用途传递数据中断安全优先级继承<strong>队列</strong>任务间数据传输✅ 数据✅❌<strong>二值信号量</strong>任务同步/中断通知❌ 仅通知✅❌<strong>计数信号量</strong>资源计数管理❌ 计数✅❌<strong>互斥锁</strong>资源独占保护❌ 锁❌✅<strong>任务通知</strong>轻量同步可选 32位值✅❌</p>
<h2>六、关键避坑指南</h2>
<ol>
<li><strong>中断中不能用互斥锁</strong>，只能用信号量（带 <code>FromISR</code> 后缀的 API）</li>
<li><strong>中断释放信号量后必须调用</strong> <code>portYIELD_FROM_ISR()</code> 检查是否需要上下文切换</li>
<li><strong>互斥锁的 Take 和 Give 必须在同一个任务中成对出现</strong></li>
<li><strong>二值信号量创建后初始为空（0）</strong>，如需初始可用需额外调用一次 <code>xSemaphoreGive()</code></li>
<li><strong>软件定时器回调中不能阻塞或死循环</strong></li>
<li><strong>共享资源必须加锁</strong>，否则会出现数据覆盖、串口乱码、I2C/SPI 时序错乱</li>
</ol>
<h2>总结</h2>
<p>信号量是 FreeRTOS 任务间通信的基石。二值信号量实现同步，计数信号量管理资源，互斥锁保护临界区，软件定时器回调处理周期任务——这四把武器掌握好了，绝大部分 RTOS 应用场景都能从容应对。</p>
