e:T14b1,<h3><strong>嵌入式产品的“产品编号”是什么？</strong></h3>
<p>嵌入式产品的<strong>产品编号</strong>通常指一个或多个用于标识设备身份的编号，常见的有：</p>
<ul>
<li><strong>硬件型号编号</strong>（Model Number / Product ID）：表示产品型号，如 “SLB-001A”，用于区分不同硬件版本。</li>
<li><strong>序列号</strong>（Serial Number）：每台设备唯一的标识，如 “SN20260315001”，用于生产追溯、售后、授权控制。</li>
<li><strong>固件版本号</strong>：标识当前烧录的软件版本，常与产品编号配合使用。</li>
<li><strong>客户定制的物料码</strong>：根据企业编码规则生成的唯一字符串。</li>
</ul>
<p>这些编号的共同目的是<strong>唯一标识设备、便于生产管理、售后服务和软件授权</strong>。</p>
<p><strong>通常需要存储到 Flash（或其他非易失存储器）中，但不是写在“代码”里，而是放在 Flash 的特定区域。</strong></p>
<p><strong>✅ 为什么需要存储到 Flash？</strong></p>
<ul>
<li>设备断电后序列号不丢失。</li>
<li>程序运行时可以读取，用于界面显示、网络上报、授权验证等。</li>
<li>生产时每个设备写入不同的序列号，不能硬编码在固件中。</li>
</ul>
<p><strong>❌ 为什么不直接写死在代码里？</strong></p>
<ul>
<li>代码是通用的，同一个固件会烧录到所有设备，不能包含唯一值。</li>
<li>如果硬编码，每个设备都需要编译不同固件，效率极低且易出错。</li>
</ul>
<h3><strong>常见的存储方案</strong></h3>
<p><strong>存储位置 适用 场景特点</strong></p>
<p><strong>MCU 内部 Flash 独立区域</strong>（如最后几页） 低成本、无外部存储器 需占用部分 Flash，注意擦写寿命和代码分区</p>
<p><strong>外部 EEPROM / Data Flash</strong> 需要频繁修改或寿命要求高 可靠性好，读写方便</p>
<p><strong>电子标签</strong>（如 RFID、NFC） 需要物理标识和电子读取结合 非接触式，常用于防伪</p>
<p><strong>安全芯片</strong>（如 ATECC508A） 需要高安全性、防克隆 序列号不可篡改，支持加密认证</p>
<p><strong>OTP / eFuse</strong>（一次性写入区） 永久不变、防篡改 烧录后不可修改，适合唯一 ID</p>
<p><br><br><br></p>
<h3><strong>在程序里如何使用？</strong></h3>
<p><strong>1. 写入（生产时操作）</strong></p>
<p>通常由生产线工具（烧录工装）完成，流程如下：</p>
<ul>
<li>通过串口、USB 或 SWD 发送写序列号命令。</li>
<li>程序收到指令后，将序列号写入 Flash 预留区。</li>
<li>写入后添加校验（如 CRC），防止损坏。</li>
<li>最后置标志位表示序列号已写，防止重复写入。</li>
</ul>
<p>示例 Flash 地址划分：</p>
<pre><code class="hljs language-cpp"><span class="hljs-number">0x08000000</span> - <span class="hljs-number">0x0803FFFF</span> : 应用程序代码 (<span class="hljs-number">256</span> KB)
<span class="hljs-number">0x08040000</span> - <span class="hljs-number">0x0805FFFF</span> : 用户数据区 (<span class="hljs-number">128</span> KB，用于存序列号、参数)
</code></pre>
<p><strong>2. 读取（运行时调用）</strong></p>
<p>在初始化时从固定地址读出序列号，校验通过后使用。</p>
<pre><code class="hljs language-cpp"><span class="hljs-function"><span class="hljs-type">const</span> <span class="hljs-type">char</span>* <span class="hljs-title">get_serial_number</span><span class="hljs-params">(<span class="hljs-type">void</span>)</span> </span>{
    <span class="hljs-keyword">return</span> (<span class="hljs-type">const</span> <span class="hljs-type">char</span>*)FLASH_SERIAL_NUMBER_ADDR;
}
</code></pre>
<p><strong>3.安全注意事项</strong></p>
<ul>
<li>序列号写入区应设置<strong>读保护</strong>，防止被外部直接读出。</li>
<li>重要产品序列号可配合<strong>数字签名</strong>，防止伪造。</li>
<li>使用 OTP 区域可保证不可更改，但需提前规划。</li>
</ul>
<h2><strong>整体生产流程</strong></h2>
<ol>
<li><strong>开发阶段</strong><br>
编写通用固件，代码中预留一个“产品信息区域”（如内部 Flash 的末尾扇区，或外部 EEPROM）。固件启动时会检查该区域是否已有有效编号。</li>
<li><strong>生产烧录</strong><br>
将同一个固件烧录到所有设备（通过 SWD、串口 ISP 等方式），此时产品信息区域是空的（全 <code>0xFF</code> 或未初始化）。</li>
<li><strong>生产写入编号</strong><br>
设备上电，固件检测到产品信息区域无效（空白），自动进入“等待写入编号”模式。<br>
产线工人/自动化系统通过<strong>串口、USB 或专用测试点</strong>向设备发送一条指令，包含唯一的序列号。<br>
固件收到后，将序列号写入 Flash 数据区，并校验成功，同时设置一个“已写入”标志。<br>
写入完成后，设备重启或自动进入正常工作模式。</li>
<li><strong>正常运行</strong><br>
设备再次上电时，固件从 Flash 数据区读取序列号，用于显示、上报、授权等。</li>
</ol>
