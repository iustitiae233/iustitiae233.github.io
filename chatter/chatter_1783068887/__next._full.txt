34:T2a3f,<h2><strong>一、Flash 分区表 —— 给你的 Flash “划地盘”</strong></h2>
<h3><strong>1. 为什么要分区？</strong></h3>
<p>就像硬盘分 C 盘、D 盘，Flash 也得划出不同的功能区，<strong>让升级过程中新固件的下载、校验、搬移都不会破坏当前正在运行的程序</strong>。</p>
<h3><strong>2. 一个最典型的 STM32F4 分区设计（1MB Flash）</strong></h3>
<p>假设芯片 Flash 总大小 1MB，起始地址 <code>0x08000000</code>。</p>
<p><strong>分区名起始地址大小作用Bootloader</strong><code>0x08000000</code>64KB上电第一行代码，负责验签、搬运固件、跳转<strong>App 主区</strong><code>0x08010000</code>448KB当前运行的应用程序 (APP)<strong>下载暂存区</strong><code>0x08080000</code>448KB接收 OTA 新固件，差分还原也在这里<strong>参数区</strong><code>0x080F0000</code>64KB存升级状态、版本号、断点续传偏移量等</p>
<blockquote>
<p>如果你做 <strong>A/B 面升级</strong>（更稳），那就不要暂存区，而是两个同样大小的 App 分区：<code>APP_A (0x08010000)</code> 和 <code>APP_B (0x08060000)</code>，互相切换。<br>
上面的例子是 <strong>暂存区+还原</strong> 方案，适合差分升级，ROM 刚好够用。</p>
</blockquote>
<h3><strong>3. 分区表如何落地到代码里？</strong></h3>
<p><strong>① 头文件中用宏定义地址和大小</strong>（bootloader、app 代码共用）</p>
<p>c</p>
<pre><code class="hljs language-cpp"><span class="hljs-comment">// flash_partition.h</span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> FLASH_BASE            0x08000000UL</span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> BOOTLOADER_SIZE       0x10000   <span class="hljs-comment">// 64KB</span></span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> APP_SIZE              0x70000   <span class="hljs-comment">// 448KB</span></span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> DOWNLOAD_SIZE         0x70000</span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> PARAM_SIZE            0x10000</span>

<span class="hljs-meta">#<span class="hljs-keyword">define</span> BOOTLOADER_START      FLASH_BASE</span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> APP_START             (FLASH_BASE + BOOTLOADER_SIZE)          <span class="hljs-comment">// 0x08010000</span></span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> DOWNLOAD_START        (APP_START + APP_SIZE)                  <span class="hljs-comment">// 0x08080000</span></span>
<span class="hljs-meta">#<span class="hljs-keyword">define</span> PARAM_START           (DOWNLOAD_START + DOWNLOAD_SIZE)        <span class="hljs-comment">// 0x080F0000</span></span>
</code></pre>
<p><strong>② 链接脚本 .ld 文件里限制代码存放范围</strong><br>
APP 的链接脚本必须告诉编译器：<strong>代码只能放在</strong> <code>APP_START</code> <strong>开始的区域</strong>。</p>
<p>ld</p>
<pre><code class="hljs language-cpp"><span class="hljs-comment">/* STM32F407VG_APP.ld */</span>
MEMORY
{
  <span class="hljs-built_in">FLASH</span> (rx) : ORIGIN = <span class="hljs-number">0x08010000</span>, LENGTH = <span class="hljs-number">448</span>K
  <span class="hljs-built_in">RAM</span>   (rwx) : ORIGIN = <span class="hljs-number">0x20000000</span>, LENGTH = <span class="hljs-number">128</span>K
}
</code></pre>
<p>这样生成出来的 <code>app.bin</code>，最开头的中断向量表就天然在 <code>0x08010000</code>。</p>

<h2><strong>二、中断向量偏移量 —— 让 CPU 找到“对的菜单”</strong></h2>
<h3><strong>1. 为什么要设偏移量？</strong></h3>
<p>CPU 响应中断时，会到一个固定的寄存器 <code>SCB->VTOR</code> 指明的地址去找<strong>中断服务函数入口表</strong>。</p>
<ul>
<li>芯片刚上电，<code>VTOR</code> 默认指向 <code>0x00000000</code>（映射到 <code>0x08000000</code>），那里是 <strong>Bootloader</strong> 的向量表。</li>
<li>一旦我们要执行 APP，CPU 必须去 <code>0x08010000</code> 找 <strong>APP 自己的向量表</strong>，否则中断一来，设备就死机或乱跳。</li>
</ul>
<p>这就是“中断向量表重映射”：<strong>把 VTOR 的值从 Bootloader 的地址改成 APP 的地址</strong>。</p>
<h3><strong>2. 配置位置：链接脚本 + 代码配合</strong></h3>
<p><strong>第一步：链接脚本定义 APP 的基地址</strong></p>
<p>上面 <code>.ld</code> 文件已经指定了 <code>FLASH</code> 起始地址 <code>0x08010000</code>，编译出来的第一个 32 位数（初始 SP）和第二个 32 位数（Reset_Handler）就在这个地址。<strong>向量表位置已经定了。</strong></p>
<p><strong>第二步：代码里设置 VTOR 寄存器</strong></p>
<p>必须在 APP 运行的第一时间设置，通常放在 <code>system_stm32f4xx.c</code> 里的 <code>SystemInit()</code>，或者在 <code>main()</code> 最开头手动加。</p>
<p><strong>找到/修改</strong> <code>system_stm32f4xx.c</code> <strong>中的宏：</strong></p>
<p>c</p>
<pre><code class="hljs language-cpp"><span class="hljs-meta">#<span class="hljs-keyword">define</span> VECT_TAB_OFFSET  0x10000   <span class="hljs-comment">/* 偏移 = APP_START - FLASH_BASE */</span></span>
</code></pre>
<p>这个宏会在 <code>SystemInit</code> 里被写到 <code>SCB->VTOR</code>：</p>
<p>c</p>
<pre><code class="hljs language-cpp">SCB->VTOR = FLASH_BASE | VECT_TAB_OFFSET;
</code></pre>
<p>等效于 <code>SCB->VTOR = 0x08000000 | 0x10000; // 0x08010000</code></p>
<p><strong>对于 Keil 环境：</strong> 在 Target Options → Target → IROM1 里设好 <code>0x08010000</code>，再在代码里加 <code>SCB->VTOR = 0x08010000;</code>。</p>
<p><strong>第三步：Bootloader 跳转前要不要设？</strong></p>
<p>通常 <strong>Bootloader 只需要校验 APP，然后跳转</strong>，跳转前可以把 <code>SCB->VTOR</code> 设为 APP 的地址，但 APP 启动后仍会自己再设一次（安全起见）。所以 <strong>APP 自己必须设</strong>。</p>
<p>跳转的典型代码（Bootloader）：</p>
<p>c</p>
<pre><code class="hljs language-cpp"><span class="hljs-function"><span class="hljs-type">void</span> <span class="hljs-title">jump_to_app</span><span class="hljs-params">(<span class="hljs-type">uint32_t</span> app_addr)</span> </span>{
    <span class="hljs-type">uint32_t</span> app_sp = *(<span class="hljs-keyword">volatile</span> <span class="hljs-type">uint32_t</span>*)app_addr;
    <span class="hljs-type">uint32_t</span> app_reset_handler = *(<span class="hljs-keyword">volatile</span> <span class="hljs-type">uint32_t</span>*)(app_addr + <span class="hljs-number">4</span>);

    <span class="hljs-comment">// 设置栈顶指针</span>
    __set_MSP(app_sp);
    <span class="hljs-comment">// 可选：将 VTOR 指向 APP 向量表</span>
    SCB->VTOR = app_addr;
    <span class="hljs-comment">// 跳转到 APP 的复位处理函数</span>
    ((<span class="hljs-built_in">void</span>(*)())app_reset_handler)();
}
</code></pre>
<blockquote>
<p>注意：跳转前必须关中断、恢复时钟等，具体看正点原子等例程。</p>
</blockquote>

<h2><strong>三、OTA 升级架构（含差分、断点）—— 从头到尾跑一遍</strong></h2>
<p>把上面“分区表 + 向量偏移”套进一个完整的静默升级流程里，你就能看到它们是如何联动工作的。</p>
<h3><strong>设备正常运行时（APP 运行）</strong></h3>
<ul>
<li>APP 的向量表在 <code>0x08010000</code>，VTOR 已经设好。</li>
<li>后台线程检测到服务器有更新，获取 <strong>差分包</strong> 的 URL、大小、签名。</li>
</ul>
<h3><strong>静默下载阶段（APP 仍在前台工作）</strong></h3>
<ol>
<li>APP 通过 HTTP Range 请求，从 0 开始下载差分包，<strong>边下载边写入下载暂存区</strong>（<code>0x08080000</code>）。</li>
<li>每写 1KB 或一个扇区，就把 <strong>已接收长度</strong> 记录到参数区（掉电续传用）。</li>
<li>如果下载中断重启，APP 会先读参数区，知道从哪个偏移量继续请求，实现断电续传。</li>
<li>全部下载完毕后，对整个差分包做 <strong>SHA256</strong>，再用预置公钥验签。通过后，在参数区写 <strong>“升级包就绪”标志</strong>，并注明是差分包。</li>
</ol>
<h3><strong>触发升级（策略点）</strong></h3>
<ul>
<li>设备夜间重启，或用户关机后上电。</li>
<li>芯片先跑 <strong>Bootloader</strong>（<code>0x08000000</code>）。</li>
</ul>
<h3><strong>Bootloader 阶段 —— 核心处理</strong></h3>
<ol>
<li>
<p><strong>读取参数区</strong>，发现有升级就绪标志。</p>
</li>
<li>
<p><strong>安全验证</strong>：再次校验下载区差分包签名，确保不是伪造（防止参数区被篡改）。</p>
</li>
<li>
<p><strong>差分还原</strong>（如果包是差分类型）：</p>
<ul>
<li>Bootloader 读取当前 APP 区固件（<code>0x08010000</code>）作为旧版本。</li>
<li>将差分包+旧固件通过差分算法还原成完整新固件，<strong>输出到下载暂存区自身，或是另一个临时缓冲</strong>（此处需要 RAM/Flash 空间规划，例如把暂存区后半部分当输出，小心覆盖）。</li>
<li>还原完成后，新固件就放在下载暂存区（或指定地址）。</li>
</ul>
</li>
<li>
<p><strong>搬移/切换固件</strong>：</p>
<ul>
<li><strong>方案A（暂存区覆盖）</strong>：把下载暂存区的新固件按扇区擦写，拷贝到 APP 主区（<code>0x08010000</code>）。此时 APP 区被覆盖，这就是 <strong>OTA 最关键的“覆写”</strong>。</li>
<li><strong>方案B（A/B分区）</strong>：假设有 APP_B 区（<code>0x08060000</code>），直接把新固件还原/解压到 APP_B，然后修改启动参数指向 B 区。</li>
</ul>
</li>
<li>
<p><strong>验签新固件</strong>（安全启动链）：对新写入的 APP 区做完整镜像签名校验，以防搬运过程中出错。</p>
</li>
<li>
<p><strong>清除升级标志</strong>，设置启动标志（如果 A/B）或保持默认。</p>
</li>
<li>
<p><strong>设置 VTOR =</strong> <code>APP_START</code>，跳转执行新 APP。</p>
</li>
</ol>
<h3><strong>新 APP 启动</strong></h3>
<ul>
<li>执行 <code>SystemInit</code>，<code>SCB->VTOR</code> 再次被设为 <code>0x08010000</code>。</li>
<li>程序正常运行，联网上报“升级成功”。</li>
</ul>
